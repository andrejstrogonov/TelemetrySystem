# Техническое задание на Electron-монитор TelemetrySystem

Версия: 0.1, Rev A

## 1. Назначение

Electron-приложение работает на компьютере оператора и показывает прохождение кадров через одну плату TelemetrySystem. Оно подключается к `J4 PC_MONITOR` как USB CDC COM-порт STM32G0B1CBT6. Генератор Owon HDS242S подключается к компьютеру отдельным USB COM-портом и настраивается через SCPI.

Приложение не подключается к аналоговому входу J2, не прошивает FPGA и не заменяет программаторы J5-J7. Прошивка выполняется отдельно: STM32 через J5 SWD, FPGA1 через J6 JTAG, FPGA2 через J7 JTAG.

## 2. Подключение оператора

1. Подключить выход Owon HDS242S к `J2 SIG_IN`.
2. Подключить USB Owon к компьютеру для SCPI.
3. Подать на плату 7...12 В DC через J1.
4. Подключить `J4 PC_MONITOR` к компьютеру USB-кабелем.
5. Запустить Electron, выбрать COM-порт STM32 и нажать Connect.
6. Нажать Start capture и запустить тестовый сигнал Owon.

Owon и TelemetrySystem являются разными COM-устройствами. Приложение должно показывать имя, VID/PID и скорость каждого выбранного порта, чтобы оператор не перепутал USB Owon с USB CDC платы.

## 3. USB CDC протокол J4

Физический канал: USB Full Speed, виртуальный COM-порт STM32, 3,3-В логика внутри платы. Рекомендуемая скорость виртуального порта: 921600 baud; USB-пакетирование не должно зависеть от baudrate, но значение используется для совместимости терминальных инструментов.

### 3.1. Бинарный кадр

Все многобайтные числа передаются little-endian.

| Поле | Размер | Значение |
|---|---:|---|
| `sync` | 2 | `0xAA55` |
| `version` | 1 | `0x01` |
| `type` | 1 | тип события или команды |
| `length` | 2 | размер payload |
| `sequence` | 4 | счётчик кадра |
| `timestamp_us` | 8 | время STM32 в микросекундах |
| `payload` | N | данные события |
| `crc32` | 4 | CRC-32/MPEG-2 по `version..payload` |

Payload события `FRAME_TRACE`:

| Поле | Размер | Значение |
|---|---:|---|
| `direction` | 1 | 0 internal, 1 output, 2 command |
| `stage` | 1 | ADC, FPGA1, FPGA2, STM32, RS485 |
| `data_length` | 2 | число байт наблюдаемого блока |
| `crc_status` | 1 | unknown, ok, error |
| `ecc_status` | 1 | none, corrected, uncorrectable |
| `anomaly` | 1 | 0/1 |
| `snapshot_ready` | 1 | 0/1 |
| `latency_us` | 4 | задержка от ADC до события |
| `data` | N | первые N байт или hash полного блока |

Для защиты пропускной способности приложение может получать только metadata и первые 32 байта data. Режим `FULL_PAYLOAD` включается отдельной командой и используется для отладки.

### 3.2. Команды Electron

Команда передаётся тем же кадром с `type=COMMAND`.

| Команда | Назначение |
|---|---|
| `CONNECT` | запрос версии и состояния |
| `START_CAPTURE` | начать выдачу FRAME_TRACE |
| `STOP_CAPTURE` | остановить трассировку |
| `READ_STATUS` | запросить питание, температуры, версии и флаги |
| `REQUEST_SNAPSHOT` | запросить сохранённый аварийный снимок |
| `SET_TEST_MODE` | включить/выключить инъекцию ошибок |
| `SET_PAYLOAD_MODE` | metadata или full payload |
| `CLEAR_COUNTERS` | очистить счётчики ошибок и sequence |

STM32 должен отвечать `ACK` или `NACK` с кодом ошибки. Команда не должна блокировать обработку измерительного потока.

## 4. Окно приложения

Главное окно состоит из следующих областей:

- **Connection**: COM-порт платы, состояние USB, версия прошивки, Connect/Disconnect;
- **Owon link**: отдельный COM-порт генератора, идентификация `*IDN?`, выбранный тест;
- **Pipeline view**: ADC -> FPGA1 -> FPGA2 -> STM32 -> RS-485;
- **Frame table**: timestamp, stage, direction, sequence, length, CRC, ECC, anomaly, latency;
- **Counters**: received, dropped, CRC errors, corrected ECC, uncorrectable ECC, snapshots;
- **Snapshot**: просмотр и экспорт аварийного окна;
- **Log**: фильтр по stage, type, sequence и времени;
- **Export**: CSV и JSONL без изменения исходных кадров.

Цветовая индикация: зелёный для штатного прохождения, жёлтый для ECC corrected или anomaly, красный для CRC error/ECC uncorrectable/power fault. В приложении должна отображаться причина, а не только цвет.

## 5. Требования к надёжности приложения

- отключение USB не должно завершать приложение;
- после переподключения приложение должно повторить `CONNECT` и показать разрыв на временной шкале;
- повреждённые кадры сохранять в raw-log и помечать CRC error;
- ограничить оперативный буфер интерфейса, например 10000 событий, с записью продолжения в файл;
- не отправлять команды прошивки через J4;
- не открывать одновременно J4 двумя процессами без явного сообщения оператору;
- сохранять настройки портов, но проверять VID/PID перед автоматическим подключением.

## 6. Связь с железом

| Канал | Разъём/устройство | Программа |
|---|---|---|
| Аналоговый сигнал | J2 SIG_IN | Owon HDS242S output |
| Управление генератором | USB Owon | SCPI/serialport |
| Мониторинг платы | J4 PC_MONITOR | Electron USB CDC |
| Прошивка STM32 | J5 MCU_PROG | ST-LINK/V3 или совместимый SWD |
| Прошивка FPGA1 | J6 FPGA1_PROG | Gowin USB Programmer/JTAG |
| Прошивка FPGA2 | J7 FPGA2_PROG | Gowin USB Programmer/JTAG |
| Внешняя телеметрия | J3 EXT_LINK | RS-485 приложение или шлюз |

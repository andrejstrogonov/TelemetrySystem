# Техническое задание на Electron-монитор TelemetrySystem

Версия: 0.1, Rev A

## 1. Назначение

Electron-приложение работает на компьютере оператора и показывает телеметрию одной платы TelemetrySystem через существующий локальный HTTP endpoint `/status`. Компьютерный сервер получает поток платы через внешний USB-RS-485 адаптер на `J3 EXT_LINK`. Генератор Owon HDS242S подключается к компьютеру отдельным USB COM-портом и настраивается через SCPI.

Приложение не подключается к аналоговому входу J2, не управляет напрямую USB-интерфейсом платы, не прошивает FPGA и не заменяет программаторы J5-J7. Прошивка выполняется отдельно: STM32 через J5 SWD, FPGA1 через J6 JTAG, FPGA2 через J7 JTAG.

## 2. Подключение оператора

1. Подключить выход Owon HDS242S к `J2 SIG_IN`.
2. Подключить USB Owon к компьютеру для SCPI.
3. Подключить Mean Well NGE12E12-P1J к J1 и подать на плату 12 В DC.
4. Подключить `J3 EXT_LINK` к компьютеру через USB-RS-485 адаптер.
5. Запустить сервер телеметрии, затем Electron и подключиться к существующему `/status`.
6. Запустить тестовую осциллограмму Owon.

Owon и USB-RS-485 адаптер являются разными COM-устройствами. Сервер должен позволять выбрать адаптер, а Electron продолжает использовать HTTP-контракт `/status` без изменений.

## 3. Контракт с сервером

Electron использует существующий HTTP endpoint `/status` и существующую JSON-модель. Сервер отвечает за выбор USB-RS-485 COM-порта, чтение кадров `J3 EXT_LINK`, преобразование их в JSON и обслуживание локального API. `J4 SERVICE_USB` не является каналом мониторинга Electron. Новые бинарные USB CDC кадры или изменения протокола Electron для Rev A не требуются.

## 4. Окно приложения

Главное окно состоит из следующих областей:

- **Connection**: состояние локального сервера `/status`, доступность платы, версия прошивки;
- **Owon link**: отдельный COM-порт генератора, идентификация `*IDN?`, выбранный тест;
- **Pipeline view**: ADC -> FPGA1 -> FPGA2 -> STM32 -> RS-485;
- **Frame table**: timestamp, stage, direction, sequence, length, CRC, ECC, anomaly, latency;
- **Counters**: received, dropped, CRC errors, corrected ECC, uncorrectable ECC, snapshots;
- **Snapshot**: просмотр и экспорт аварийного окна;
- **Log**: фильтр по stage, type, sequence и времени;
- **Export**: CSV и JSONL без изменения исходных кадров.

Цветовая индикация: зелёный для штатного прохождения, жёлтый для ECC corrected или anomaly, красный для CRC error/ECC uncorrectable/power fault. В приложении должна отображаться причина, а не только цвет.

## 5. Требования к надёжности приложения

- потеря HTTP-соединения или RS-485 не должна завершать приложение;
- после восстановления связи приложение должно повторно получить `/status` и показать разрыв на временной шкале;
- повреждённые кадры сохранять в raw-log и помечать CRC error;
- ограничить оперативный буфер интерфейса, например 10000 событий, с записью продолжения в файл;
- не использовать `J4 SERVICE_USB` как канал телеметрии;
- сервер не должен открывать один COM-порт USB-RS-485 одновременно из нескольких процессов;
- сохранять выбор адаптера и проверять его наличие перед подключением.

## 6. Связь с железом

| Канал | Разъём/устройство | Программа |
|---|---|---|
| Аналоговый сигнал | J2 SIG_IN | Owon HDS242S output |
| Управление генератором | USB Owon | SCPI/serialport |
| Мониторинг платы | J3 EXT_LINK + USB-RS-485 адаптер | сервер телеметрии -> HTTP `/status` -> Electron |
| Прошивка STM32 | J5 MCU_PROG | ST-LINK/V3 или совместимый SWD |
| Прошивка FPGA1 | J6 FPGA1_PROG | Gowin USB Programmer/JTAG |
| Прошивка FPGA2 | J7 FPGA2_PROG | Gowin USB Programmer/JTAG |
| Сервис платы | J4 SERVICE_USB | сервис STM32, не telemetry endpoint Electron |

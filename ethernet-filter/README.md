# Двухпортовый Ethernet-фильтр для Gowin

Отдельный проект на базе существующей аппаратной платформы: входной и выходной RJ45-порты, двусторонняя передача Ethernet-кадров и блокировка кадров целочисленной линейной регрессией в FPGA.

```text
Ethernet IN ─ MagJack/PHY 0 ─┐      ┌─ PHY 1/MagJack ─ Ethernet OUT
                             ├ Gowin┤
Ethernet IN ◀ MagJack/PHY 0 ─┘ FPGA └─ PHY 1/MagJack ◀ Ethernet OUT
```

Кадры пересылаются в обоих направлениях. Каждый путь работает независимо: PHY 0 RX → PHY 1 TX и PHY 1 RX → PHY 0 TX. FPGA принимает кадр целиком, проверяет преамбулу, длину и Ethernet CRC-32, рассчитывает линейную оценку по признакам заголовка и либо отбрасывает кадр, либо передаёт сохранённые байты без изменения.

## Состав

- `rtl/gowin_ethernet_filter_top.v` — верхний модуль для Gowin GW1NR-9C.
- `rtl/rmii_filter_channel.v` — один store-and-forward тракт с двумя буферами кадров.
- `rtl/linear_regression_classifier.v` — фиксированная целочисленная оценка и порог.
- `tools/train_regression.py` — OLS-обучение весов из CSV, стандартная библиотека Python.
- `examples/packet_labels.example.csv` — только пример формата обучающих данных.
- `hardware/BOM.csv`, `NETS.csv`, `POWER_TREE.md` — начальная логическая аппаратная спецификация.
- `constraints/ethernet_filter.sdc` — входной такт 50 МГц RMII.

## Модель

Вектор признаков, вычисляемый по Ethernet-заголовку:

| Бит | Признак |
|---:|---|
| 0 | multicast/broadcast MAC назначения |
| 1 | EtherType ARP |
| 2 | EtherType IPv4 |
| 3 | EtherType IPv6 |
| 4 | один VLAN-тег (0x8100 или 0x88A8) |
| 5 | IPv4 TCP |
| 6 | IPv4 UDP |
| 7 | IPv4 TCP/UDP порт назначения 23 |
| 8 | неизвестный EtherType |

Вычисление: `score = bias + Σ(weight[i] * feature[i])`. FPGA блокирует кадр, когда `score >= threshold`. Коэффициенты и порог — signed 24-bit constants; умножений нет, только сложение выбранных констант. Параметры превращаются в логику при синтезе и хранятся в bitstream.

Встроенная демонстрационная модель блокирует IPv4 TCP/UDP с портом назначения 23. Это пример проверки тракта, а не готовая политика безопасности. Обучите коэффициенты по собственным размеченным кадрам и проверьте результат на отдельной выборке до загрузки в устройство:

```powershell
python ethernet-filter/tools/train_regression.py ethernet-filter/examples/packet_labels.example.csv
```

CSV должен содержать колонки `multicast,arp,ipv4,ipv6,vlan,tcp,udp,port23,unknown,unwanted`, все значения 0/1. Скрипт выполняет обычную регрессию наименьших квадратов с bias, затем квантует веса с масштабом 256 и порогом 128. Он печатает готовые named parameter overrides для экземпляра `gowin_ethernet_filter_top`. Пример CSV содержит синтетические строки, его нельзя считать обученным сетевым профилем. Если признаки в реальной выборке линейно зависимы, соберите более разнообразные метки: обучатель сообщит о вырожденной матрице.

## Аппаратные допущения

- Два PHY 10/100 RMII (базовый кандидат LAN8742A) и общий входной REF_CLK 50 МГц.
- RTL рассчитан только на 100BASE-TX full-duplex. Линию `phy*_link_100fd` должен подать менеджер PHY после настройки и проверки link mode через MDIO. В проектной схеме для этого предусмотрены существующий STM32 и общая шина MDC/MDIO. До подтверждения обоих линков передача с соответствующего выхода отключена.
- Пример PHY должен быть сконфигурирован для объявления только 100BASE-TX full-duplex с autonegotiation; режим 10 Мбит/с не поддержан.
- RMII RX тракт ожидает байты преамбулы/SFD перед DA и FCS в кадре. Переходник PHY должен передавать FCS в MAC-интерфейс; эти предположения нужно подтвердить на выбранном PHY и настройке перед разводкой.
- На каждом направлении два кадра по 1530 байт (преамбула/SFD + тегированный Ethernet кадр до 1522 байт с FCS). При заполненных двух слотах новый кадр отбрасывается; Ethernet pause/back-pressure не формируется.
- Парсер понимает один VLAN-тег и базовый IPv4 IHL. Для IPv6 учитывается только EtherType. IPv6 extension headers, произвольный разбор полезной нагрузки, IP-фрагментация и reassembly не реализованы.
- Не назначены выводы корпуса QN88. До запуска синтеза/Place & Route заполнить pin constraints согласно плате, проверить размещение BSRAM и RMII timing в Gowin EDA.
- Входной сигнал `phy*_link_100fd` поступает от STM32/MDIO отдельно для каждого порта; он должен быть `1` только после успешной настройки PHY и проверки 100BASE-TX full-duplex.

## Питание

Сохранён источник той же платформы: адаптер 12 В DC / 1 А, входная защита, 5V5, 1V2 и 3V3. FPGA получает 1V2 core и 3V3 I/O; PHY и интерфейс RMII питаются от 3V3. Шина 5V5 оставлена в дереве питания и не подаётся на цифровые выводы. Ethernet-разъёмы должны иметь трансформаторную развязку; PoE не предусмотрен. Перед выпуском платы проверить ток двух PHY, FPGA и MCU относительно адаптера и теплового режима регуляторов.

Это логический стартовый проект и синтезируемый RTL, но не готовая к изготовлению PCB: нужны pin assignment, PHY-management firmware/RTL, проверка временных диаграмм RMII и подтверждение конкретных MPN/footprint по datasheet.
